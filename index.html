DATA & SECURITY

Payroll data requires a serious deployment model.

CARRR's public version should be used only with fictional or anonymised information. Real payroll use would require appropriate private hosting, access controls, authentication, retention rules, logging, encryption, organisational policies and a security/privacy review appropriate to the employer and jurisdiction.

FAQ

Understand the role CARRR plays.

Does CARRR replace payroll software?+

No. CARRR is designed as a payroll control and pre-release review layer around an existing payroll system.

Does CARRR pay employees?+

No. READY TO RELEASE is a control decision. The payroll professional returns to the payroll system to perform the actual payroll release or payment process.

Why are there two payroll files?+

The Payroll Input / Expected Data represents what you expect before processing. The Pre-Release Payroll Output is exported from the payroll system after calculation but before final release. CARRR uses the two to reconcile expected versus processed values.

Do I have to inspect all 500 employees?+

The design goal is the opposite. CARRR applies repeatable checks across the population and directs attention toward exceptions, warnings and failures that need human review.

What file formats does the current app support?+

The current CARRR prototype can accept common payroll sources including CSV and Excel, with newer preprocessing for Word, PDF and image/OCR-based inputs. Extracted data should always be reviewed before payroll decisions are made.

Can I use real payroll data in the public trial?+

No. Use fictional or anonymised data in a public deployment. Real payroll information should only be used after a suitable private and secure deployment has been implemented and reviewed.
